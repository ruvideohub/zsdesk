# Аудит 0.3.23 и план улучшения

Проверено: сборка `8aacb0c` (CI run `44812151882` — зелёный), дерево после неё.
Метод: чтение кода и разбор по всем крейтам, механические выборки (размеры, тесты, `unsafe`,
проглоченные ошибки, английские строки, точки запуска процессов, упаковка).
Чего в аудите нет и быть не может: прогона интерфейса — здесь нет Windows, поэтому всё, что
касается «нажал — сработало», помечено отдельно.

Этот документ заменяет `plan-0.3.23.md`: пункты 1–2 оттуда сделаны, остальное вошло в волны
ниже.

## P1 — то, что противоречит принятым решениям или ломает поставку

**P1-1. Виджеты по-прежнему дети панели.**
`crates/aura-dock/src/dock.rs:5560` и `:5629` запускают `widgets.exe` с `--dock <hwnd>`, а
`crates/aura-service/src/launch.rs:40` прямо объясняет, почему виджетов нет в списке
компонентов. Это противоречит `docs/components.md` («запускать может только служба») и вашей
формулировке «запуск и настройки запуска — в отдельный сервис».
Следствия: панель упала — часы и загрузка исчезли; включить/выключить виджеты из службы
нельзя; настройки виджетов рисует панель, а не сам виджет.
Сделать: `widgets.exe` умеет жить без панели (`--component clock|system` без `--dock`),
в `COMPONENTS` появляется строка «Виджеты рабочего стола», панель перестаёт их запускать и
только помнит их расположение.

**P1-2. Контрол-центр на английском, и часть подписей виджетов тоже.**
`crates/aura-dock/src/control_center.rs:379–428`: «Control Center», «Wi-Fi», «Bluetooth»,
«Airplane Mode», «Night Light», «Do Not Disturb», «Light Mode»/«Dark Mode», «Sound»,
«Microphone», «Brightness», «Muted», «Not supported». Плюс четыре строки вообще без перевода:
`widgets/paint.rs:1157, 2568, 2699, 2738` («Use Claude Code or Codex on this PC…», «This monitor
doesn't report its brightness…», «Pin apps in Launchpad…», «Click to write a note.»).
Таблица переводов уже есть (`strings.rs`, `tr()`), её просто не вызывают. Правило «язык один —
русский» (§3 закрыт) сейчас не выполняется.
Сделать: обернуть в `tr()`, добавить недостающие ключи («Wi-Fi», «Bluetooth», «Not supported»).

**P1-3. Упаковка разошлась с архитектурой.**
`scripts/package.ps1` всё ещё собирает «редакции» (`DesktopOnly`, `Desktop`), копирует только
`AuraExplorer.exe` и `AuraDock.exe`, требует `manifest.json`, тянет
`ShellRoutingControl.exe`, `AuraExplorerRevealRouter.dll` и MinHook, а в README пишет
«AuraExplorer.exe 启动时自动带起 AuraDock.exe» — ровно то поведение, которое §9 отменил.
`packaging/windows/aura.iss:38` падает без `manifest.json`, которого нет в `dist` воркфлоу.
Значит: текущая поставка (6 exe + DLL + `install.ps1`, всё через службу) и официальный
установщик — два разных продукта; кто соберёт `setup.exe`, получит старую модель запуска.
Сделать: либо переписать `package.ps1`/`aura.iss` под реальный набор файлов и службу, либо
явно вывести их из поставки и оставить один путь (`install.ps1` + zip). Второе честнее, первое
нужно для установщика.

**P1-4. `--settings` есть только у архиватора.**
`crates/aura-service/src/launch.rs:102` — единственная программа с `settings: &["--settings"]`.
Проводник и панель такого аргумента не знают (`grep '"--settings"'` даёт только `aura-arc` и
саму службу). Ваше правило «из службы должны открываться настройки любого компонента» сейчас
выполнено для одного компонента из трёх.
Сделать: `AuraExplorer.exe --settings` и `AuraDock.exe --settings` открывают свои настройки
(у проводника это уже существующее окно настроек, у панели — её страница настроек), служба
получает по строке «Настройки…» на каждый компонент.

**P1-5. Поведение почти не проверяется, а UI — не проверяется вообще.**
77 `#[ignore]` в проводнике, 23 в `aura-windows`: это тесты, которым нужны настоящие окна, и в
CI они не идут. Окно архиватора живёт второй раунд без единого нажатия. Все «работает» в моих
отчётах означают «компилируется и проходит юнит-тесты движка».
Сделать: первый UI-тест на offscreen-окне архиватора (кнопка «Настройки» переключает флажок и
пишет файл; набор текста фильтрует таблицу; Delete убирает строку), затем разобрать список
`#[ignore]`: что можно включить в CI, а что пометить «только руками» и внести в чек-лист.

## P2 — качество и предсказуемость

**P2-1. Проглоченные ошибки без следа.** `let _ =` встречается 265 раз в проводнике и 387 в
панели. Часть — законное «нечего делать с ошибкой закрытия окна», но рядом есть места, где
отказ означает «человек нажал и ничего не произошло». Нужен общий счётчик: ошибка, которую
некуда вернуть, попадает в журнал компонента с контекстом.

**P2-2. Битые настройки молча заменяются значениями по умолчанию** —
`aura-dock/src/config.rs:350`, `aura-service/src/launch.rs:190`. Человек теряет раскладку
панели без единого слова. Нужно: рядом `*.bad`, в окне сообщение «настройки не прочитаны,
сохранена копия».

**P2-3. Четыре разных места настроек:** `%APPDATA%\AuraExplorer`, `%APPDATA%\AuraUI\Dock`,
`%APPDATA%\AuraUI\Service`, `%APPDATA%\AuraUI\AuraArc`. Решить одно правило (скорее всего
`%APPDATA%\AuraUI\<компонент>` для всего нового) и не менять его больше.

**P2-4. В окне архиватора нет правого щелчка** — `WM_RBUTTONDOWN`/`WM_CONTEXTMENU` не
обрабатываются, меню в таблице нет. Для файлового менеджера это обязательный жест: «Извлечь»,
«Копировать», «Удалить», «Свойства», «Открыть расположение архива».

**P2-5. У архиватора нет журнала.** Ошибки видны только в строке состояния и исчезают при
следующем действии. Нужен `auraservice.log`-подобный файл, чтобы «не распаковалось» можно было
разобрать.

**P2-6. Проводник запускает `fences.exe` сам** (`window/input.rs:907`). Пункт меню «показать
сетки» обходит службу: служба считает компонент выключенным, а он работает.

**P2-7. Размеры файлов.** `aura-dock/src/dock.rs` — 6 063 строки, `widgets/paint.rs` — 3 076,
`aura-explorer/src/desktop/host.rs` — 3 258. Это не ошибка, но каждая правка в них — работа
вслепую; разбивать по мере касания, а не отдельным «рефакторинг-раундом».

## P3 — мелочи

- `aura-platform` без тестов (107 строк — стоит покрыть хотя бы разбор путей).
- 94 `#[allow(dead_code)]` — часть скрывает недоделки; пересмотреть при касании.
- Две системы перевода: `aura_core::i18n::text` (ключ = китайская строка) и
  `aura_dock::strings::tr` (ключ = английская). Свести к одной при следующей правке доки.
- Версия в README и в установщике не связана с `Cargo.toml` — сверять при выпуске.

## Что проверено и в порядке

- Архиватор: движок (stored/deflate, UTF-8, CRC, дополнение без пересжатия, атрибуты папок,
  сверка оглавления с числом записей, удаление/копирование строки) — 23 теста, зелёные.
- Окно архиватора: работа в отдельном потоке, прогресс, выделение набором, ни одного
  блокирующего вызова в потоке окна.
- Настройки службы: терпимый разбор, ротация журнала после 256 КБ, один мьютекс на службу.
- Проводник: ни одной английской строки в интерфейсе (все через `i18n::text`).
- Поставка: все шесть программ собираются одной сборкой, `install.ps1` знает про каждую,
  `dist` содержит ровно то, что перечислено в `install.ps1`.

## План улучшения — волнами

Волна = один коммит = одна сборка. Порядок выбран так, чтобы первым уходило то, что человек
видит каждый день.

**Волна 1 — язык и вход в настройки (P1-2, P1-4).** Контрол-центр и подписи виджетов
по-русски; `--settings` у панели и проводника; в службе у каждого компонента «Настройки…».
Приёмка: в сборке нет ни одной английской подписи в панели; из окна службы открываются
настройки всех трёх компонентов и архиватора.

**Волна 2 — виджеты уходят в службу (P1-1).** `widgets.exe` живёт без панели и получает своё
окно настроек; служба поднимает его как компонент и перезапускает при падении; панель только
хранит раскладку.
Приёмка: панель закрыта — часы и загрузка на месте; выключил виджеты в службе — исчезли;
два экземпляра не поднимаются.

**Волна 3 — поставка (P1-3).** `package.ps1` и `aura.iss` под реальный набор файлов и службу
(или вывод их из поставки с объяснением в README); README без «Explorer запускает док».
Приёмка: собранный `setup.exe` ставит 6 exe + DLL, поднимает службу, не создаёт вторую запись
автозапуска и не обещает старых механизмов.

**Волна 4 — архиватор до продукта (P2-4, P2-5, затем tar/gz).** Контекстное меню в таблице,
журнал, затем чтение `tar`, `tar.gz`, `tgz`, `gz` тем же движком.
Приёмка: правый щелчок по строке даёт меню; журнал объясняет любую неудачу; `.tar.gz`
открывается в окне и распаковывается командой.

**Волна 5 — проверяемость (P1-5).** Первый UI-тест архиватора (offscreen), ревизия 100
`#[ignore]`: что включается в CI, что остаётся за чек-листом.
Приёмка: `cargo test` в CI нажимает кнопку и проверяет результат, а не только собирает код.

**Волна 6 — устойчивость (P2-1, P2-2, P2-3).** Единый журнал компонентов, `.bad` для битых
настроек, одна папка настроек, счётчик проглоченных ошибок.
Приёмка: испорченный JSON не стирает конфигурацию молча; ошибка без возврата видна в журнале.

Волны 1–2 меняют поведение, волна 3 — то, как продукт ставится, волны 4–6 — то, как он живёт
дальше. Начинать с 1: она маленькая, видимая и снимает два противоречия с принятыми правилами.
