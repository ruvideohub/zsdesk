# Dock как замена панели задач Windows 11

Цель: сохранить существующий визуальный стиль Dock и обеспечить удобную и безопасную замену панели задач. Это план последовательной работы, а не утверждение о полной совместимости.

## Этап 1 — безопасность системной панели

- До скрытия панели Windows Dock запускает независимый сторож и ждёт подтверждения, что тот открыл процесс Dock. Если запуск не удался, панель Windows остаётся доступной, настройка отключается и показывается сообщение.
- Пока панель скрыта, Dock проверяет сторож. Если тот завершился, Dock возвращает панель Windows и отключает подмену. При штатном возвращении панели предыдущий сторож останавливается; повторное включение создаёт новый со свежим состоянием.
- После перезапуска Explorer используется прежний сторож, а не создаётся ещё один. Карточки рабочего стола проверяют существование окна Dock и при потоке одних таймеров.
- `taskbar_guard.rs` имеет изолированные тесты запуска, отказа и тайм-аута; CI исполняет их на Windows независимо от исключённого полного набора `aura-dock`.

Это не гарантирует восстановление при одновременном отказе обоих процессов, зависании всей системы или принудительном завершении сторожа одновременно с Dock. Окончательная проверка требует интерактивной Windows 11.

## Этап 2 — трей и окна: первые исправления

- Dock повторяет попытку запуска перехватчика трея, если при старте не нашёл панель Explorer. Значки, скрытые самими приложениями через `NIS_HIDDEN`, не показываются ни на полосе, ни в переполнении; пользовательское скрытие по-прежнему отправляет значок в переполнение.
- При повторном добавлении значка с GUID обновляется ID для callback, но GUID-only изменение не подменяет его нулём. Определение окон Dock при поиске панели Explorer учитывает актуальное имя `AuraDock.exe` и путь текущего исполняемого файла.
- Неудачное определение идентичности окна больше не кэшируется навсегда; повторное использование HWND другим процессом не наследует прежнюю идентичность. Обновление окон также запрашивается после смены заголовка и завершения перемещения или изменения размера.
- Изолированные policy-тесты включены в Windows CI. Они не моделируют Explorer или реальные сообщения приложений; перезапуск Explorer, callback и задержку регистрации трея по-прежнему необходимо проверять интерактивно.

## Этап 3 — резервирование места для панели

- Dock обрабатывает `ABN_POSCHANGED` и повторно запрашивает позицию после изменений других панелей. Повторное объявление неизменного прямоугольника пропускается, чтобы ограничить цикл взаимных уведомлений appbar.
- Если регистрация `ABM_NEW` не удалась, Dock не считает полосу зарезервированной. При повторной регистрации после `TaskbarCreated` он снимает возможную старую регистрацию и делает ещё одну попытку.
- Проверки политики сравнения прямоугольников запускаются отдельно в CI. Поведение Explorer, конкуренция нескольких appbar и многоэкранные конфигурации требуют интерактивного испытания на Windows 11.

## Проверки на реальной Windows 11, ещё необходимые

1. При включённом и выключенном автоскрытии Windows: запустить Dock, закрыть штатно, завершить через диспетчер задач; проверить видимость панели и исходное состояние автоскрытия.
2. Многократно переключать замену панели, затем завершить Dock; отдельно перезапустить Explorer. Убедиться, что старые сторожа не возвращают устаревшее состояние.
3. Принудительно остановить сторож, убедиться, что панель Windows вернулась и появилась ошибка; проверить поведение при невозможности запуска сторожа.
4. Трей: набор уведомлений, скрытые значки, действия и контекстное меню популярных приложений, Explorer restart, стабильность идентификаторов.
5. Запущенные и закреплённые приложения: несколько окон одного приложения, модальные окна, UWP, свёрнутые, прогресс и уведомления, виртуальные рабочие столы.
6. Мониторы: подключение/отключение, смена основного, разные DPI, полноэкранные приложения, автоскрытие и расположение резервируемой полосы.
7. Клавиатура, экранный диктор, высокий контраст, масштаб текста, Windows Start/поиск/уведомления, языки и системные индикаторы. Сравнить поведение и доступность с панелью Windows 11.
8. Проверить потребление ресурсов на простое и при большом числе окон; повторить установку, обновление и удаление с восстановлением системной панели.

## Следующие технические участки для аудита

- Перехват трея в `tray.rs` зависит от поведения Shell и не доказывает полноту протокола Windows 11; требуется реальный набор приложений и проверка icon version 4, уведомлений и переподключения Explorer.
- `tracker.rs` описывает правила окон как приблизительные; нужно сверить отображение и группировку с реальной панелью задач, включая виртуальные рабочие столы и окна с владельцами.
- Проверить конфликты appbar, перезапуск Explorer, состояния автоскрытия и ошибки Shell API на реальной Windows 11.
- CI пока не исполняет весь набор тестов `aura-dock` и `laminar-sys`. Протокол сторожа проверяется отдельно, но это не замена GUI/integration тестам.
