# Правый щелчок: одно меню, меню файла (0.3.24)

Короткая записка о том, что изменено и что осталось непроверенным. Подробности для
пользователя — в `CHANGELOG.md` (раздел «Правый щелчок: меню файла, а не меню программы»)
и в `docs/user-guide.md` (раздел «右键菜单»).

## Что было

Первый ПКМ собирал отдельную страницу из собственных строк AuraExplorer
(`context_menu_common.rs`, `flyout_menu::show` в воркере) и не содержал ни одного пункта
оболочки. Отсюда «пустое и кривое меню» и второй ПКМ, плюс надпись «正在加载右键菜单…»
через 250 мс ожидания.

## Что стало

- **Одна страница — настоящее меню `IContextMenu`.** `context_menu_common` больше не строит
  страницу: он отдаёт только группу своих строк (`application_rows`), а воркер
  (`context_menu_process.rs`, одинаково в explorer и fences) вставляет её под строки оболочки
  через `aura_windows::desktop::insert_menu_items`.
- **Нумерация.** Строки оболочки — `SHELL_FIRST..=SHELL_LAST`, свои — `APP_FIRST = 0x7000` и
  далее в порядке вставки; дети подменю считаются тем же счётчиком. `insert_menu_items`
  возвращает identities ровно в порядке вставки и останавливается на первой неудаче, чтобы
  список оставался префиксом (иначе номер команды указал бы не на ту строку). Выбранный номер
  декодируется через `application_rows` → `application_choice`.
- **Стиль.** Меню с нашими строками всегда классическое (`track_standalone` принудительно
  ставит `modern=false, drawn=false`): ни нативное представление Windows 11, ни рисованное не
  умеют показывать чужие строки. Поэтому же такое меню собирается полным `populate()`, а не
  `populate_compact()`.
- **Состав группы:** копировать путь, «Открыть с помощью» (перечисленные приложения +
  «Выбрать другое приложение…»), сжать в ZIP, создать ярлык (один файл), распаковать (один
  архив), терминал (пустое место папки). Вырезать/копировать/удалять/вставлять больше не
  дублируется — это команды оболочки.
- **Никакой надписи во время подготовки** (`window/context_menu.rs`): `loading_notified`,
  `started` и оба сообщения удалены; `foreground_is_menu_worker` теперь проверяется всегда, без
  оглядки на `quick_first`.
- **`ContextMenuOptions.quick_first` удалён**; `ContextMenuPreferences.full_menu_first` больше
  никем не читается и оставлен только для чтения старых профилей. Пункт «优先显示完整菜单»
  убран из меню настроек, `context-menu-full-first` больше не принимается.
- **Удалено как мёртвое:** `aura-windows/src/shell/quick_menu.rs` (`QuickMenu`, `QuickAction`),
  `insert_top`/`insert_item` в `aura-fences/src/desktop/mod.rs`, показ «常用 страницы» в воркере
  вместе с проверкой `aura_windows::flyout::is_open()`.

## План строк отделён от Shell

Решение о том, какие строки показывать, собрано в `rows_for(options, target, handlers)`
(`context_menu_common.rs`, одинаково в explorer и fences): на вход — только цель и
настройки, на выходе — строки и identities в порядке вставки. `application_rows` осталась
тонкой обёрткой, которая строит `Target` из запроса. Это позволило прогнать план тестами,
не разрешая ни одного PIDL.

Попутно закрыты три дыры, найденные при разборе кода:

- **Фон папки с живым представлением** вставлял строки, но трекал меню с
  `application_count = 0` — клик по нашим пунктам молча ничего не делал. Появился
  `ShellMenu::track_background_view_at`; оба воркера переведены на него.
- **Shift+ПКМ по пустому месту** (расширенные глаголы) оставлял группу выключенной, но меню
  всё равно считалось «нашим» — терялись презентер Windows 11 и расширения. Счётчик теперь
  всегда `application_rows.len()`, поэтому пустая группа идёт прежним путём.
- **Нераскрываемый путь при одном выбранном элементе** давал строки «Открыть с помощью» и
  «Создать ярлык», которые ничего не делали (`selected` пуст). Обе строки привязаны к
  `Target.addressed`.

## Проверено

- `rustfmt --edition 2021 --emit stdout` по всем изменённым `.rs` — разбираются.
- **План строк: 11 тестов зелёные** (`./.restore/stand/run.sh`). Стенд в `.restore/stand/`
  копирует `context_menu_common.rs` как есть и подменяет только три вещи, которые модуль
  берёт извне: `aura_core::i18n::text`, `ContextMenuOptions` и `MenuRow`. Тесты гоняют
  `rows_for` на описанных вручную целях, поэтому не зависят от разрешения PIDL.
- `scripts/check-translations.py` (1151 запись), `scripts/check-resources.py`,
  `scripts/check_fences_boundary.py` — проходят.
- Литералы подписей сверены с `crates/aura-core/resources/strings.en.json`: все семь
  (`复制路径`, `打开方式`, `选择其他应用…`, `压缩为 ZIP 文件`, `创建快捷方式`,
  `解压到当前文件夹`, `在此处打开终端`) имеют английские переводы.

## Не проверено (и не может быть здесь)

- **Типы Windows-крейтов.** `TRACK_POPUP_MENU_FLAGS` сначала выглядел подозрительно: такого
  макроса нет ни в репозитории, ни в `windows` crate. По исходникам `windows 0.62.2` это не
  макрос, а newtype-структура с `pub const fn` конструктором (`WindowsAndMessaging/mod.rs`),
  и `TPM_LEFTALIGN`/`TPM_TOPALIGN` там же — код верен, править нечего. Проверить это
  компилятором на этой машине по-прежнему нельзя (см. ниже).
- **Сборка.** `cargo check -p aura-windows --target x86_64-pc-windows-msvc` не проходит: build
  script собирает `native/minhook` и `native/shell_menu.cpp` через `cc`, а для MSVC на Linux нет
  `windows.h`. Linux-таргет не годится: `aura-windows` целиком под `#[cfg(windows)]`.
  Type-check Windows-крейтов на этой машине невозможен — нужна сборка на Windows.
- `aura-ui` (и всё, что его тянет) не собирается из-за неполного path-крейта `/home/user/zsui`.
- Windows-only интеграционные тесты (`context_menu_process_tests.rs`,
  `desktop/context_menu_regression.rs`) не запускались: правки в них — только удаление
  `QuickMenu`/`ENTERED`/`QUICK` фикстур.

## Восстановление правок

`crates/` не всегда выживает между сессиями. `.restore/` содержит всё, чтобы вернуть работу
на чистый `e159c18` одной командой: `git checkout -- crates/ && python3 .restore/apply.py`.
Скрипт идемпотентен (второй прогон ничего не меняет) и переписывает целиком те файлы, где
правок больше, чем можно надёжно вписать заменой строк: `context_menu_common.rs`,
`context_menu_process.rs` (отдельно для explorer и fences — воркеры не идентичны),
`shell/menu.rs`, `desktop.rs`, `aura-ui/src/menus.rs`.

## Что проверить на живой Windows

1. ПКМ по файлу: первая страница = полное меню 7-Zip/Git/«Отправить»/«Открыть с помощью»/
   «Свойства» + наша группа под разделителем.
2. ПКМ по пустому месту папки и по фенсу: то же самое + «Открыть терминал здесь».
3. Выбор своей строки (`copypath`, `compress`, `shortcut`, `openwith:N`) исполняется ровно
   один раз и возвращает `CreatedItem`/статус в хост.
4. Пункт из подменю «Открыть с помощью» не сдвигает соседние команды: номера детей идут одним
   счётчиком.
5. Меню у нижнего/правого края не уходит за рабочую область.
6. Во время подготовки меню на окне ничего не появляется.
7. Shift+ПКМ по пустому месту: меню остаётся расширенным (презентер Windows 11 и сторонние
   расширения на месте), наших строк в нём нет.
8. ПКМ по элементу, путь которого не раскрывается (например, из виртуального пространства
   имён): строк «Открыть с помощью» и «Создать ярлык» нет, остальные работают.
