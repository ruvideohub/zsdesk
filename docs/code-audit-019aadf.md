## Архитектура и действующие ограничения

| Слой | Назначение и границы |
|---|---|
| `aura-core` | Модели/общая логика, атомарная запись и ресурсы; используется несколькими продуктами. |
| `aura-platform` | Платформенные контракты; `aura-windows` содержит реализацию Windows/Shell. Наличие контракта не доказывает его использование всеми путями. |
| `aura-fences-model`, `aura-fences` | Модель и самостоятельная программа Fences; Windows host управляет окнами, Explorer и watchdog. |
| `aura-ui`, `aura-windows` | Общий UI и Windows-интеграция; крупные Shell-модули активно используются Fences. |
| `aura-dock`, `laminar-sys` | Панель, Launchpad, сервисы/коннекторы, визуализация и дочерние процессы desktop-карточек. |

Текущий `packaging/bundle.json` и `scripts/check_slim_bundle.py:14–18,30` задают Dock-only payload; Fences поставляется отдельным пакетом. Не возвращать совместный установщик/супервизор, не запускать Fences из Dock. Fences может читать тему Dock без запуска процесса. Календарь, радио и погода — desktop-карточки, не ярлыки в Dock; заметки из UI/runtime удалены, старые поля сохранены ради совместимости, пользовательские файлы не трогать. На вид эталон — Dock и Launchpad, в том числе для Fences и настроек. Desktop-карточки сейчас отдельные процессы, но зависят от владельца Dock (`crates/aura-dock/src/host.rs:49–71`); слово «самостоятельные» здесь означает расположение на рабочем столе, а не автономный от Dock продукт.

### Уже действующие защиты

Dock отказывается сохранять поверх невалидного/нечитаемого профиля и пишет через атомарный helper (`crates/aura-dock/src/config.rs:510–525`). Fences перед скрытием значков записывает recovery-маркер и проверяет готовность watchdog (`crates/aura-fences/src/desktop/host.rs:538–552`); файловые операции имеют отдельные механизмы отката. Радио проверяет размер данных, у загрузки есть таймаут и отключены редиректы (`crates/aura-dock/src/radio_catalogue.rs:32–55`); плейлист разбирается с лимитами. Секреты коннекторов хранятся через Windows Credential Manager (`crates/laminar-sys/src/secrets.rs:1–45`), сетевые ответы общего HTTPS-клиента ограничены 16 МиБ (`crates/laminar-sys/src/http.rs:96–106`). Всё это полезные основы, а не гарантия отсутствия ошибок.

## Реестр находок

### P0 — защита данных и восстановление рабочего стола

**A1. Fences молча подменяет повреждённую конфигурацию на defaults и позже может записать их поверх файла.** Подтверждён путь кода, последствия зависят от дальнейшей работы. `crates/aura-fences/src/desktop/host.rs:3086–3096` превращает любую ошибку чтения/JSON в `DesktopConfig::default()`; `desktop/mod.rs:319–335` использует результат при обычном старте, `host.rs:365–375,451–457` сохраняет конфигурацию при завершении и изменениях. В watchdog тот же loader определяет, нужно ли восстанавливать скрытые иконки (`desktop/mod.rs:416–425`): при нечитабельном marker решение может быть ошибочным. Это не доказательство фактической потери профиля или значков в проведённых тестах.

**Решение:** различать отсутствующий файл и повреждённый/недоступный; не перезаписывать исходник при ошибке, показать восстанавливаемое состояние и путь к файлу, сохранить копию, продумать отдельный надёжный recovery-маркер без ложного восстановления пользовательски скрытых значков. Уникальные временные имена, проверяемая атомарная замена и межпроцессное согласование host/watchdog. **Приёмка:** тесты отсутствующего, битого, заблокированного и недоступного файла, сбоя до/после замены и аварийной остановки; старый профиль побайтно сохранён; изолированная Windows-проверка всех состояний системных значков.

**A2. Частичная миграция Dock может больше не повториться.** Подтверждён путь; возникновение требует ошибки ввода-вывода. `crates/aura-dock/src/config.rs:400–413` создаёт новую папку до копирования и игнорирует ошибки; её существование отменит последующие попытки. Исходные файлы при этом не удаляются. **Решение:** мигрировать в отдельную временную папку, проверять все операции и завершать маркером/атомарным переключением; предусмотреть безопасное возобновление, отчёт и ручное восстановление, не затирать новый профиль. **Приёмка:** инъекция ошибки каждой копии/создания/смены имени и повторный запуск сохраняют закрепления и размещение, старый источник остаётся нетронут.

### P1 — надёжность, доступность и релизы

**A3. Единая очередь системных операций: подтверждённое блокирование некоторых задач, задержки остальных требуют измерения.** `crates/aura-dock/src/services.rs:105–135,165–180,229–236`: неограниченный `channel`, один worker; после подключения Wi-Fi он трижды ждёт по 1,5 с, пока другие операции не исполняются. Поиск файлов уже коалесцируется в партии, погода выделена в `LatestWorker`; эти защиты не покрывают всю очередь. Ошибки старта worker и отправки игнорируются. **Решение:** выделить медленные операции, ограничить очереди и coalesce только для команд, где допустим latest-wins; сохранять порядок действий пользователя, явные ошибки и корректное завершение. **Приёмка:** управляемый задержанный Wi-Fi mock плюс шквал slider/search — неограниченного роста нет, последний slider доходит, UI сообщает отказ; latency p50/p95/p99 измеряются до и после на Windows.

**A4. Создание потока на job и залипающий `busy` при ошибке старта.** Подтверждено для пути: `crates/aura-dock/src/widgets/hub.rs:249–319,331–335,375–397` выставляет `busy` до запуска и снимает при ответе, а ошибка `spawn` игнорируется; при отказе создания потока ответа не будет. Без fault injection реальная частота неизвестна. **Решение:** ограниченный исполнитель для сетевых/обычных задач, отдельный STA для диалога выбора файла, завершение с ошибкой при отказе старта, timeout/generation для устаревших ответов; не прерывать Win32/COM небезопасным способом. **Приёмка:** отказ запуска, зависающий провайдер, отмена, закрытие окна, быстрые повторные запросы и восстановление обрабатываются без вечного `busy` и без неограниченного числа потоков.

**A5. Замена локального радио-плейлиста не полностью восстанавливаема.** `crates/aura-dock/src/radio_import.rs:41–60` использует общие `.new/.bak`, удаляет старую backup и игнорирует ошибку её восстановления. Условный риск сбоя/параллельного импорта; его влияние требуется воспроизвести, старый файл может оставаться в `.bak`. **Решение:** уникальная временная запись, сериализация импортов, явная ошибка восстановления, сохраняемая копия и сценарий обнаружения после сбоя. **Приёмка:** Windows fault-injection на каждом rename/write и двух одновременных импортах; последняя валидная копия доступна и пользователь видит причину.

**A6. High contrast и прозрачность применены не ко всем поверхностям.** Подтверждено ограничение реализации: комментарий и состояние в `crates/aura-dock/src/ui.rs:46–56`; desktop host применяет системные предпочтения (`desktop_environment.rs:10–52`), а `dock.rs:6452–6464` обрабатывает лишь указанное изменение темы. Это не исчерпывающий результат визуальной приёмки. **Решение:** общий policy слой цветов/прозрачности для Dock, Launchpad, меню, настроек, Fences и карточек; без стекла в high contrast и при отключённой прозрачности; цвета системы и контрастный фокус. Сверяться с `docs/visual-consistency-audit.md`, Dock/Launchpad — референс. **Приёмка Windows:** светлая/тёмная/контрастные темы, прозрачность on/off и живое переключение, 100/150/200% DPI, клавиатурный фокус, скриншоты каждого состояния.

**A7. Тестовый и release gate зависят от ручного запуска.** `.github/workflows/dock-build.yml:10–20` — ручной dispatch и push на `main` по путям, без `pull_request`; feature-ветка сама этот workflow не запускает. Workflow не пустой: есть полноценные Windows-сборки, тесты и smoke (`:403–445`), но в репозитории также есть native `#[ignore]` тесты, требующие отдельной среды. GitHub Actions используются по тегам (`:32–44`), а не immutable SHA. Проведение release до завершения всех тестов опасно, если потребитель использует ранее опубликованный артефакт, не проверив статус run; сам факт загрузки артефакта не означает release. **Решение:** PR gate для релевантных путей, обязательный Windows build/test/статические guards, Linux тесты переносимых слоёв; изолированный Windows job для безопасного набора native tests, ручная матрица остальных; выпуск только после зелёного gate; фиксация actions по проверенному commit SHA с обновлением и ZSUI по ревизии. **Приёмка:** заведомо красный тест и smoke блокируют merge/release; `#[ignore]` описаны с безопасной командой, зависимостями и частотой запуска.

**A8. Подпись не должна сообщать об успешном release, когда её нет.** `scripts/sign.ps1:35–39,47–76` при отсутствии signtool выходит с успехом, при исключении лишь warning; есть self-signed fallback. Результат проверки печатается, но явно не является gate. Это характеристика скрипта, не утверждение, что конкретный опубликованный релиз подписан или имел уязвимость. **Решение:** отделить dev/self-signed и release mode, для release требовать ожидаемый доверенный сертификат, timestamp, проверку каждого EXE и установщика, завершать с ошибкой при отказе. Секреты не выводить; временный PFX создавать с уникальным именем и ограниченными правами. **Приёмка:** нет сертификата/неверная подпись/отсутствует timestamp → release запрещён; опубликованные hashes и проверка подписи доступны пользователю.

### P2 — архитектура, безопасность и производительность

**A9. Большие модули замедляют безопасные изменения.** `aura-dock/src/dock.rs` 7 351 строка, `aura-fences/src/desktop/host.rs` 3 361, `aura-dock/src/widgets/paint.rs` 3 080, `aura-windows/src/shell/packaged_overlay.rs` 2 462, `packaged_state_worker.rs` 1 988. Это метрика сопровождаемости, не доказанная медлительность. Выносить по вертикальным сценариям и с тестами: состояние/политики без Win32, команды и обработку результатов отдельно от оконного слоя, зафиксировать ownership, жизненные циклы COM и взаимодействие между процессами. Избегать большого переписывания и поломки сохранённых данных.

**A10. Reentrant события могут пропасть.** `crates/aura-dock/src/dock.rs:940–952` при неудачном `try_borrow_mut` не исполняет callback; wndproc использует его, например, для мыши (`:6009–6012`). При каких реальных вложенных вызовах события действительно теряются — **гипотеза**. Добавить счётчик/трассировку без персональных данных и воспроизведение вложенных сообщений; критичные события откладывать/коалесцировать, а не запускать вложенный event loop под `RefCell`.

**A11. Сетевые ошибки и приватность.** По требованию пользователя базовый радио-каталог — `http://radio.pervii.com/top_radio_russian.m3u`: без TLS содержимое и направления потоков могут быть подменены в сети. Сохранять совместимость с указанным адресом, показать предупреждение и использовать HTTPS только при проверенной доступности, не выдумывать защищённый endpoint. Ограничения и запрет редиректов уже есть. Общий HTTP-клиент `crates/laminar-sys/src/http.rs:99–108` объединяет ошибку чтения и EOF: усечённый ответ может быть возвращён как успешный; распространять ошибку, тестировать частичное чтение и таймаут. Секретные адреса не записывать в логи: общий `http.rs:59` включает исходный URL в ошибку `bad url`, хотя коннектор `common.rs` отфильтровывает этот случай (`common.rs` функция `net`); проверить всех текущих и будущих вызывающих и убрать URL из источника ошибки. Коннектор calendar намеренно хранит приватный URL в Credential Manager (`calendar.rs:21–27,397–402`). Не утверждается, что секрет фактически утёк.

**A12. Нагрузка desktop-виджетов и IPC — измерить.** `crates/aura-dock/src/host.rs:51–83` для каждой карточки ставит 250-мс таймер, обновляет окружение раз в секунду; радио синхронно отправляет `WM_COPYDATA` с timeout 100 мс (`desktop_radio.rs:24–29`). Ограничение timeout и отдельные процессы уже есть. Реальный расход CPU/батареи и заметность задержек не измерены. Выполнить ETW/WPA или эквивалентные замеры idle/активного режима, sleep/resume, нескольких мониторов и 2 646 станций; оптимизировать только по данным. Замеры не должны содержать имена приватных станций или URL.

**A13. Доступность управляющих элементов требует отдельной проверки.** Поверхности преимущественно рисуются вручную; поиск `WM_GETOBJECT`, `IRawElementProvider`, `IAccessible` в Dock/Fences не нашёл реализаций провайдеров, при этом UI Automation используется в тестах. Это не доказывает полное отсутствие любой доступности Windows. Провести Narrator/Inspect/keyboard аудит и добавить необходимые UIA name/role/state/action, клавиатурные альтернативы drag/drop и видимый фокус. Приёмка — управляемые Dock, Launchpad, меню, настройки и карточки без мыши и с Narrator.

## Лишний и потенциально мёртвый код

1. **Безопасная очистка:** дублированный `#[cfg(windows)]` `crates/aura-fences/src/main.rs:12–13`. После удаления — обычная Windows-сборка и тесты.
2. **Кандидат на упрощение после проверки путей:** `crates/aura-dock/src/updater.rs:1–8,17–34,57–80` сохраняет интерфейс неработающего автообновления и недостижимые при текущем stub состояния. Проверить все ветви UI и совместимость настроек; исправить описание с учётом раздельных установщиков и не обещать автообновление. Удалять состояния только вместе с потребителями и тестами.
3. **Документация устарела:** `docs/component-dependency-audit.md` описывает бывшие AuraExplorer/AuraService и общий installer, что расходится с текущими `Cargo.toml` и `scripts/check_slim_bundle.py`. Это исторический снимок, не инструкция по текущей упаковке. Пометить архивным с ссылкой на `docs/fences-split.md` и данный отчёт; актуализировать комментарии workflow и updater. Не возвращать удалённые компоненты ради старого текста.
4. **Не удалять без проверки:** `#[allow(dead_code)]` и неиспользуемые на Linux Win32 callbacks могут быть входами нативного кода, `cfg` или тестов; `widgets/hub.rs:579–580` sample data живёт в визуализации (`widgets/paint.rs:190`) и screenshot sheet, не мусор; большие Explorer/Shell-подсистемы имеют потребителей Fences. Поля старых настроек заметок сохранять ради совместимости. Проверять ссылки, Windows/feature builds, callback registration, сериализацию, installer и обратную совместимость прежде чем удалять. `crates/aura-platform/src/shell.rs` — контракты, но не считать весь crate мёртвым: `aura-windows/src/enumerate.rs` его использует.

Оценки времени/производительности без Windows-профилирования и размера команды не даны. При релизе сохранять обратную совместимость профилей, проверять обновление со старой версии и откат; не удалять пользовательский файл заметок или старый профиль при миграции.

## Windows-приёмка перед релизом

- Чистая установка, обновление и удаление **каждой** программы отдельно и при совместной установке; профиль/данные сохраняются, Dock не запускает/не закрывает/не удаляет Fences, и наоборот.
- Explorer restart, crash/kill Dock и Fences, восстановление taskbar и значков с различным исходным состоянием, выход watchdog; заранее сохранить состояние тестовой машины.
- Несколько мониторов и DPI, AppBar, Z-order, перетаскивание, клики, контекстные меню, tray, high contrast, прозрачность, масштаб текста и настройки.
- Календарь, погода, радио на desktop, локальный M3U, default HTTP, потеря сети, пустой/битый/большой плейлист, работа/пауза/перезапуск аудио. Вложенные M3U/PLS не поддерживаются; импорт по URL ещё не реализован.
- Тесты приватного desktop и Shell из `#[ignore]` запускать только в безопасной изолированной среде согласно их требованиям, с фиксацией результата; GUI smoke и CI не подменяют ручную приёмку.
